# Публикация ExProfit.by

Инструкция для ручной публикации статического сайта через FileZilla. Публикация выполняется только по отдельному разрешению владельца. Документ описывает порядок действий и не подтверждает текущее состояние хостинга. Адрес подключения, протокол, учётные данные и путь папки действующего сайта в проекте не заданы; используйте сведения владельца или хостинга.

## Состав публичной поставки

Текущий комплект состоит из восьми файлов: пять в корне публичной папки, `index.html` в подкаталоге `crm-automation/` и два изображения в `assets/images/`. Сохраняйте эту структуру при передаче:

| Файл | Назначение |
| --- | --- |
| [index.html](../index.html) | Основная страница, ссылки на ресурсы и SEO-метаданные. |
| [crm-automation/index.html](../crm-automation/index.html) | Посадочная страница автоматизации CRM и интеграций на Python. |
| [exprofit.css](../exprofit.css) | Готовые стили из локальной сборки. |
| [script.js](../script.js) | UTM и обработка аналитических событий. |
| [robots.txt](../robots.txt) | Правила обхода и ссылка на sitemap. |
| [sitemap.xml](../sitemap.xml) | Карта сайта с URL главной и `/crm-automation/`. |
| [assets/images/andrey-korobeynikov.webp](../assets/images/andrey-korobeynikov.webp) | Авторский портрет в разделе «О разработчике» главной, 384 × 384 px. |
| [assets/images/crm-automation-og.jpg](../assets/images/crm-automation-og.jpg) | Карточка Open Graph и Twitter для посадочной, 1200 × 630 px. |

На хостинг не загружаются `docs/`, `src/`, `tests/`, `node_modules/`, `README.md`, `AGENTS.md`, резервные копии из `backup/` и служебные файлы, включая `.git/`, `.gitignore`, `package.json` и `package-lock.json`. Не переносите корень проекта целиком. Публичная контентная основа `docs/CONTENT.md`, локальные редакционные материалы `docs/internal/EDITORIAL.md` и прототип `docs/internal/design-preview.html` не входят в поставку сайта. Правила хранения в публичном репозитории описаны в [docs/README.md](README.md#правила-хранения); исключение из поставки не ограничивает доступ к уже опубликованным файлам и истории Git.

## Подготовка

Выполните [локальную подготовку, тестирование и сборку из README](../README.md#подготовка-и-сборка). Команды сверены с [package.json](../package.json): используются встроенный Node.js test runner, проверка синтаксиса JavaScript и Tailwind CLI. Для подготовки нужны Node.js 22+ и npm; на сервер передаются готовые файлы, поэтому Node.js и установка зависимостей на хостинге не требуются.

Убедитесь, что проверки завершились успешно, а сборка создала `exprofit.css`. Главная подключает `exprofit.css?v=20261126-about-portrait` и `script.js`, посадочная — `../exprofit.css?v=20261126-about-portrait` и `../script.js`; общие ресурсы должны лежать в корне публичной папки. Версия CSS в URL обновлена для переноса портрета в раздел «О разработчике». CSS должен содержать правила `.wrap`, `.hero-bottom` и `.author-photo`. Перед передачей просмотрите подготовленный комплект локально по инструкции в README, включая `/crm-automation/`: сервер должен отдавать `crm-automation/index.html` как индекс каталога.

## Публикация через FileZilla

1. Используйте действующее подключение к хостингу. Определите папку, из которой обслуживается именно `exprofit.by`, по настройкам домена или сведениям хостинга. Не выбирайте путь по предполагаемому имени каталога. Если назначение папки неизвестно, уточните его до замены файлов.
2. Скачайте резервную копию заменяемых файлов с хостинга и сохраните её вне публичной папки, например локально вне каталога поставки. Сохраните предыдущие HTML, JavaScript, изображения и все CSS, на которые ссылается предыдущий HTML, а также заменяемые `robots.txt` и `sitemap.xml`. Имя предыдущего CSS может отличаться от текущего. Проверьте завершение скачивания и наличие полного комплекта для отката.
3. В локальной панели FileZilla выберите подготовленные файлы, в удалённой панели проверьте папку действующего сайта. Сначала загрузите `exprofit.css`, `script.js`, `robots.txt` и оба изображения с сохранением каталога `assets/images/`. Дождитесь завершения их передачи без ошибок, прежде чем загружать HTML.
4. После ресурсов создайте в публичной папке подкаталог `crm-automation/`, если его нет, и загрузите в него посадочную `crm-automation/index.html`. Затем загрузите главную `index.html` в корень; не заменяйте её индексом посадочной. `sitemap.xml` загрузите после обеих страниц. Если любой этап не завершён, остановите передачу и восстановите согласованный комплект. Заменяйте только файлы согласованного комплекта. Не удаляйте посторонние файлы, каталоги и настройки хостинга; прежние CSS сохраняйте по правилам [отката](#откат).
5. Проверьте очередь передачи, список неудавшихся передач и журнал FileZilla. Публикация комплекта завершена только после успешной передачи всех выбранных файлов; незавершённые и ошибочные передачи нужно устранить. Затем выполните [проверки сайта](#проверка-после-публикации).

Работа с локальной и удалённой панелями, очередью загрузки и скачиванием описана в [официальной инструкции FileZilla](https://wiki.filezilla-project.org/FileZilla_Client_Tutorial_(en)).

## Кеширование

По сообщению владельца, при обновлении сайта новый HTML загружался со старым `output.css`. Публикация CSS под новым именем `exprofit.css` решила проблему. Точный источник кеширования не установлен; оснований приписывать его конкретному браузеру, хостингу или промежуточному сервису нет.

При публикации изменённого кешируемого ресурса согласованно меняйте имя файла или версию его URL и ссылку в HTML. Если меняется имя CSS, обновляйте выходной путь в обеих командах сборки, подключения в обоих HTML и состав поставки в этой инструкции, затем пересобирайте файл. Если используется версия в URL, она должна меняться вместе с содержимым, а ссылка должна вести на подготовленный ресурс. Сначала публикуйте ресурс, затем HTML со ссылкой на него.

Сейчас обе команды сборки используют постоянное имя `exprofit.css`, обе страницы подключают его с версией `?v=20261126-portrait`. Автоматического версионирования ресурсов и обновления ссылок в проекте нет; смена имени или версии выполняется вручную. Само новое имя не гарантирует отсутствие подобных проблем при последующих обновлениях. Для диагностики проверяйте адрес и содержимое реально загруженного CSS в инструментах разработчика браузера.

## Проверка после публикации

- Откройте `https://exprofit.by/` и `https://exprofit.by/crm-automation/`. Проверьте переход из CRM-блока главной на посадочную и возврат через логотип; дизайн обеих страниц должен соответствовать подготовленному комплекту.
- В инструментах разработчика проверьте загрузку CSS и JavaScript по адресам, указанным в опубликованном HTML. Для текущего комплекта это `https://exprofit.by/exprofit.css` и `https://exprofit.by/script.js`. Ответы должны содержать нужные CSS и JavaScript, без ошибок загрузки или подмены страницей HTML.
- Проверьте все пункты меню, якорные переходы и закреплённую шапку. Заголовки и клавиатурный focus не должны скрываться под ней. Проверьте мобильное отображение, включая 390 × 844 px: обе кнопки первого экрана полностью видны, горизонтального переполнения нет.
- Сверьте Telegram-контакт `https://t.me/korobey`, GitHub-профиль `https://github.com/partizan-code` и ссылки проектов с согласованными адресами в локальных HTML.
- Проверьте портрет в разделе «О разработчике» главной и отсутствие отображаемого фото автора на `/crm-automation/`. Проверьте доступность `https://exprofit.by/assets/images/crm-automation-og.jpg`: ответ должен содержать JPEG 1200 × 630 px. На посадочной `og:image` и `twitter:image` должны указывать на этот абсолютный URL; фактический вид превью зависит также от кеша социальной платформы.
- Проверьте актуальность `title` и `description` относительно подготовленного HTML, а также canonical и `og:url` каждой страницы: `https://exprofit.by/` и `https://exprofit.by/crm-automation/`.
- Убедитесь, что оба HTML не содержат `noindex` и служебных пометок «Прототип» и «Локальная дизайн-концепция».
- Проверьте доступность `https://exprofit.by/robots.txt` и `https://exprofit.by/sitemap.xml`. Ссылка на sitemap и URL обеих страниц должны соответствовать основному домену.

Успешная загрузка сайта и открытие Telegram **не подтверждают доставку аналитических событий** в Яндекс Метрику или обработчик Google Apps Script. Локальные тесты с подменой внешних запросов тоже не подтверждают production-доставку. Проверка аналитики является отдельной задачей и требует отдельного разрешения на конкретные действия и согласованного тестового окружения; технические сведения об интеграциях находятся в [ANALYTICS.md](ANALYTICS.md).

## Откат

Восстановите из резервной копии согласованный комплект предыдущих HTML, CSS, JavaScript и изображений с исходной структурой каталогов. Сначала восстановите необходимые ресурсы, затем предыдущие HTML. Для версии с адресом `/crm-automation/` восстановите `crm-automation/index.html`; для прежней версии с файлом `crm-automation.html` восстановите его в корне вместе с соответствующими ссылками главной и sitemap. При откате к версии без посадочной восстановите главную и sitemap без ссылок на неё; удаление впервые добавленной страницы согласуйте отдельно, не затрагивая посторонние файлы. Если заменялись `robots.txt` и `sitemap.xml`, восстановите и их согласованные версии. Проверьте передачу и повторите проверку сайта относительно восстановленного комплекта.

При публикации CSS под новым именем сохраняйте предыдущий ресурс доступным по прежнему адресу: он нужен для отката и старых кешированных страниц. После отката новый ресурс также может понадобиться страницам новой версии, оставшимся в кеше. Не удаляйте такие CSS вместе с заменой HTML; срок их хранения определяйте с учётом фактического кеширования, источник и сроки которого сейчас не установлены.

Резервные копии комплектов храните вне публичной папки. Сохранение ранее подключённого CSS по рабочему URL не заменяет такую резервную копию. Откат не должен затрагивать посторонние файлы и настройки хостинга.
