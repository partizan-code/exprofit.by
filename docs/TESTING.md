# Тестирование и изоляция

Документ описывает существующие автоматические тесты и ручные браузерные сценарии. Production-сервисы и реальные уведомления не нужны для локальной проверки сайта.

## Команды и их границы

Команды подготовки, проверки и сборки сохранены в [корневом README](../README.md#подготовка-и-сборка). Скрипты определены в [package.json](../package.json).

| Команда | Действие и побочные эффекты |
| --- | --- |
| `npm ci --ignore-scripts` | Устанавливает зависимости по lockfile с обращением к npm registry; изменяет `node_modules`, может писать npm cache и логи. Это подготовка среды, не тест. |
| `npm test` | Запускает `node --test`; текущие семь тестов только читают `script.js`, выполняют его в `node:vm` и используют подмены DOM и `fetch`. |
| `node --check script.js` | Проверяет синтаксис без выполнения кода и без сетевых запросов. |
| `npm run build:css` | Собирает CSS через локальный Tailwind CLI; перезаписывает `exprofit.css`. |
| `npm run watch:css` | Продолжает пересборку CSS при изменениях; также перезаписывает `exprofit.css`. |

Для текущего `npm test` npm-зависимости не требуются: тесты используют встроенные модули Node.js. В них нет загрузки `.env`, чтения production-учётных данных, записи файлов или вызова реального `fetch`. Если тесты меняются, перед запуском заново проверьте их изоляцию.

## Автоматическое покрытие

[tests/script.test.cjs](../tests/script.test.cjs) проверяет:

1. Список из пяти UTM, Unicode, пустые и повторяющиеся значения.
2. Внутренние ссылки: query/hash назначения, приоритет собственных UTM, отсутствие лишних полей и дубликатов.
3. Относительные, query-only и абсолютные ссылки того же origin.
4. Сохранение нативных якорей и внешних ссылок, включая Telegram, `mailto:` и `tel:`.
5. Подготовку `href` до активации и отсутствие отмены навигации при клике.
6. POST, `keepalive`, состав JSON и фильтрацию query в поле `url` события.
7. Перехват асинхронного и синхронного сбоя запроса, а также недоступного `fetch`.

DOM в тестах упрощён. Эти проверки не измеряют визуальный результат, доступность всей страницы, работу настоящего браузера, доставку аналитики или совместимость всех ОС.

## Изоляция браузера

Локальный HTTP-сервер не отключает интеграции из HTML. **Настройте перехват до первой загрузки страницы**, включая новые вкладки и запросы `noscript`:

- Блокируйте `https://mc.yandex.ru/*`, `https://script.google.com/*` и `https://script.googleusercontent.com/*`.
- При проверке CTA перехватывайте переходы к `https://t.me/*`; проверяйте адрес и открытие вкладки через подмену, без реального перехода или уведомления.
- Для изолированного браузерного прогона разрешайте сеть только к локальному серверу, остальные внешние запросы блокируйте. Внешние GitHub-ссылки проверяйте по `href`.
- Проверяйте журнал перехвата. Для сценариев аналитики подменяйте `fetch` ответом, ошибкой, незавершающимся Promise или отсутствующим API, не обращаясь к реальному endpoint.

Запуск сервера приведён в [README](../README.md#локальный-просмотр). Пример локального адреса после настройки изоляции: `http://127.0.0.1:8000/?utm_source=local&utm_campaign=check#portfolio`. Используйте только синтетические данные.

## Ручные браузерные сценарии

После изменений разметки, стилей или поведения повторяйте применимые проверки с изоляцией:

1. HTML5-разметка: проверяйте локально, не отправляя документы во внешний валидатор без разрешения.
2. Адаптивность: ширины **320, 390, 768, 1024 и 1440 px**, отсутствие горизонтального переполнения и соответствие согласованному дизайну. На **390 × 844 px** обе кнопки первого экрана должны полностью помещаться.
3. Навигация: все пункты меню, skip link, якоря, история «назад/вперёд», отсутствие скрытых под sticky header заголовков.
4. Клавиатура: `Tab`, `Shift+Tab`, `Enter`, видимый фокус и доступность ссылок. Проверьте `prefers-reduced-motion`.
5. UTM: разрешённые параметры, приоритет назначения, query/hash и неизменность внешних ссылок по правилам [ANALYTICS.md](ANALYTICS.md).
6. Оба основных CTA: успешная, неудачная и зависшая подменённая аналитика, отсутствие `fetch`, отключённый JavaScript. Во всех случаях нативная ссылка должна сохранять возможность открыть целевой адрес; никаких реальных запросов к Telegram.

Автоматизированного браузерного runner в репозитории нет. Эти сценарии не входят в `npm test`.

## Проверка посадочной CRM-страницы · 26 ноября 2026

После добавления `crm-automation.html` выполнены `npm test` (7/7), `node --check script.js` и `npm run build:css`. Сборка сохранила `exprofit.css` побайтно прежним: посадочная использует существующие компоненты, её источник явно зарегистрирован через `@source`.

Обе страницы проверены локальным `html-validate` с профилем `html-validate:document` без правила `require-sri` (оно требует integrity у существующих локальных ресурсов и не относится к корректности HTML). Браузерный прогон выполнен отдельно в headless Chrome 158 на macOS через временный Playwright-скрипт, без установки зависимостей в проект:

- Ширины 320, 390, 768, 1024 и 1440 px для обеих страниц: горизонтального переполнения нет, меню и отступы заголовков под sticky header работают. На 390 × 844 px обе кнопки первого экрана видны полностью. Скриншоты посадочной при 390 и 1440 px просмотрены.
- Переход с главной на посадочную и обратно сохраняет пять разрешённых UTM, включая Unicode и пустое значение; посторонний query-параметр не копируется. Собственные параметры и hash назначения имеют приоритет и сохраняются без дублей UTM.
- На посадочной проверены skip link, видимый focus, Tab/Shift+Tab/Enter, история назад/вперёд и reduced motion.
- Оба CTA посадочной открывают подменённую страницу Telegram при успешной, ошибочной и зависшей аналитике, отсутствии `fetch`, недоступном `script.js` и отключённом JavaScript. Проверены идентификаторы событий, путь посадочной в JSON, UTM и фильтрация постороннего query-параметра.

Перехват всех запросов установлен до первой навигации на уровне браузерного контекста, включая всплывающие вкладки и `noscript`. HTML/CSS/JS отдавались из локальных файлов на синтетическом origin; Метрика, Apps Script и Telegram подменены, остальные внешние запросы запрещены. Реальных аналитических событий и уведомлений не отправлялось. Настройки и срабатывание production-целей Метрики не проверялись; границы вывода описаны в [ANALYTICS.md](ANALYTICS.md#цели-cta-посадочной-crm-страницы). Windows, Safari и Firefox в этом прогоне не проверялись.

## Ранее зафиксированные результаты

До реструктуризации документации корневой README сообщал о локальной HTML5-проверке и изолированной браузерной проверке Chrome при переносе дизайна: ширины 320–1440 px из списка выше, отсутствие переполнения, все пункты меню, клавиатура, видимость фокуса и заголовков, UTM, история и reduced motion. В нём также были отмечены полностью видимые кнопки на 390 × 844 px и проверка обоих CTA при успешной, неудачной и зависшей аналитике, отсутствии `fetch` и отключённом JavaScript с подменой внешних запросов до загрузки.

Это сохранённые сведения предыдущего этапа, а не повторно выполненные проверки при редактировании документации. В прежнем README указано, что проверки в Windows, Safari и Firefox не выполнялись; новых результатов для них здесь не заявляется.

## Ограничения

Успех локальных тестов не подтверждает состояние хостинга, индексацию или доставку событий в production. Проверки после разрешённой публикации описаны в [DEPLOYMENT.md](DEPLOYMENT.md#проверка-после-публикации); реальная аналитика требует отдельного согласования и тестового окружения.
