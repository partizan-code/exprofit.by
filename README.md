# ExProfit

Одностраничный русскоязычный сайт-портфолио Андрея Коробейникова для [exprofit.by](https://exprofit.by/). Представляет Python backend, AI-интеграции, автоматизацию бизнеса, шесть проектов, информацию о разработчике и порядок работы; ссылки связи ведут в Telegram.

Статическая архитектура: HTML, обычный JavaScript и Tailwind CSS **4.1.17**. Backend и frontend-фреймворки отсутствуют. Готовый `exprofit.css` находится в корне проекта; для просмотра и работы сайта на сервере Node.js не требуется.

## Возможности и структура

- Согласованный тёмный дизайн с адаптивными блоками услуг, портфолио, информации о разработчике, этапов работы и контакта.
- Закреплённая шапка (`position: sticky`), меню разделов, ссылка пропуска к содержимому, отступы якорей и клавиатурного фокуса, поддержка `prefers-reduced-motion`.
- Сохранение пяти UTM-параметров при внутренних переходах и необязательная отправка события при нажатии контактных CTA.
- Яндекс Метрика, canonical, текстовые Open Graph metadata, `robots.txt` и sitemap.

## Подготовка и сборка

Требуются Node.js **22+** и npm. Выполняйте команды из корня репозитория; они одинаковы для macOS и Windows:

```sh
npm ci --ignore-scripts
npm test
node --check script.js
npm run build:css
```

Устанавливайте зависимости при первоначальной подготовке или изменении lockfile. Тесты и сборка выполняются локально до публикации. Сборка читает `src/input.css` и создаёт минимизированный `exprofit.css`, который подключён в `index.html`; сгенерированный файл вручную не редактируется.

Для автоматической локальной пересборки при изменениях:

```sh
npm run watch:css
```

`tailwindcss` и `@tailwindcss/cli` закреплены на версии 4.1.17; lockfile фиксирует остальные зависимости. Исходник явно сканирует только `index.html` и `script.js`, поэтому примеры в README и тестах не влияют на CSS. При добавлении нового файла с Tailwind-классами зарегистрируйте его через `@source` в `src/input.css`. Подход соответствует [документации Tailwind CLI](https://tailwindcss.com/docs/installation/tailwind-cli) и [настройке поиска классов](https://tailwindcss.com/docs/detecting-classes-in-source-files).

## Локальный просмотр

Установка зависимостей и сборка для просмотра готового сайта не нужны. При установленном Python 3 запустите статический сервер.

macOS:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Windows с Python Launcher:

```powershell
py -3 -m http.server 8000 --bind 127.0.0.1
```

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Для остановки нажмите `Ctrl+C`. Сервер предназначен только для локального просмотра; параметры описаны в [документации Python](https://docs.python.org/3/library/http.server.html#command-line-interface).

Страница сохраняет действующие интеграции и при локальном просмотре. Перед открытием изолируйте браузер: блокируйте `https://mc.yandex.ru/*`, `https://script.google.com/*` и `https://script.googleusercontent.com/*`; при проверке CTA подменяйте также переходы к `https://t.me/*`. Автоматизированная проверка должна перехватывать запросы до первой загрузки страницы. Проверка настоящей доставки аналитики требует отдельного тестового окружения.

## UTM и внешние интеграции

Список разрешённых параметров: `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`.

- Якоря меню и `#portfolio` обрабатываются браузером: query текущей страницы сохраняется, hash и история переходов работают без JavaScript. Прокрутка мгновенная, как в согласованном прототипе; `prefers-reduced-motion` также отключает анимации и переходы.
- Внутренние ссылки того же origin получают только UTM текущей страницы. Собственные query-параметры и hash назначения сохраняются; заданные в ссылке UTM имеют приоритет. Остальные параметры текущего URL не копируются. Внешние ссылки, включая Telegram, не получают UTM.
- **Google Apps Script:** `sendUTMToTelegram()` отправляет POST с JSON: `button`, `url` и пять UTM-полей (отсутствующие — `null`). Поле `url` содержит адрес страницы, только разрешённые UTM и hash. Адрес обработчика и названия полей сохранены. `fetch` использует `keepalive`; переход по обычной CTA-ссылке не ожидает ответа и работает при сбое или отключении JavaScript. Исходного кода обработчика здесь нет; доставка в Telegram не подтверждена.
- **События CTA:** обе основные кнопки показывают «Обсудить задачу» и открывают Telegram в новой вкладке. Первая отправляет прежний идентификатор `Обсудить проект`, кнопка в контактах отправляет `Написать в Телеграмм`. Текстовая ссылка `Telegram · @korobey` остаётся обычной ссылкой без отдельного события Google Apps Script.
- **Яндекс Метрика:** исходные идентификатор и настройки сохранены, включая Webvisor, карту кликов и отслеживание ссылок. `noscript` с пикселем находится в `body`.
- **Контакт и проекты:** контакт `@korobey` и ссылки на шесть репозиториев GitHub заданы в HTML. Проекты представлены с текущими статусами и ограничениями; их функциональность и работа внешних сервисов в рамках переноса дизайна не проверялись.

## Проверки

Команды приведены в разделе [«Подготовка и сборка»](#подготовка-и-сборка).

`npm test` использует встроенный Node.js test runner и подменяет DOM и `fetch`. Семь тестов проверяют UTM-список, кодирование и повторяющиеся значения, внутренние и внешние ссылки, сохранение query/hash назначения, отсутствие отмены навигации, состав события и сетевые сбои. Production-сервисы не вызываются.

При переносе дизайна выполнены локальная проверка HTML5-разметки и изолированная браузерная проверка Chrome при ширине **320, 390, 768, 1024 и 1440 px**: сравнение с прототипом, отсутствие горизонтального переполнения, все пункты меню, Tab/Shift+Tab/Enter, видимость фокуса и заголовков под шапкой, UTM, история переходов и reduced motion. На **390 × 844 px** обе кнопки первого экрана полностью видны. Оба основных CTA проверены при успешной, неудачной и зависшей аналитике, отсутствии `fetch` и отключённом JavaScript. Все внешние запросы подменены до загрузки страницы. Браузерные сценарии не входят в `npm test`; после изменений разметки повторяйте их отдельно с перехватом внешних запросов. Проверка в Windows, Safari и Firefox не выполнялась.

## Изменения и размещение

Тексты, ссылки и метаданные редактируются в `index.html`, поведение — в `script.js`, стили — в `src/input.css`. После изменения стилей или Tailwind-классов пересоберите CSS локально.

Краткий порядок публикации: локальные проверки и сборка, резервная копия, передача через FileZilla, проверка результата. [Подробная инструкция](docs/DEPLOYMENT.md) определяет состав пяти публичных файлов, исключения из поставки, порядок загрузки, работу с кешем и откат. Конфигурации хостинга и автоматического деплоя в проекте нет.

SEO-тексты перенесены из согласованной контентной основы. Canonical, `og:url`, `robots.txt` и единственный URL sitemap соответствуют `https://exprofit.by/`; подтверждение Яндекса сохранено. На основной странице нет `noindex` и ограничительной CSP прототипа. При смене домена обновляйте адреса согласованно; `lastmod` отражает дату изменения страницы.

Оставшиеся SEO-задачи: отдельное изображение для Open Graph и решение о добавлении JSON-LD после проверки данных. Новые изображения, страницы и JSON-LD на этом этапе не добавлялись. Локальные проверки не подтверждают состояние опубликованной версии, индексацию или доставку production-аналитики; проверки после публикации описаны в инструкции выше.
